# Каракули

Социальная сеть в духе классических соцсетей 2010–2015 с «нарисованным от руки» оформлением.
Чистые HTML5 / CSS3 / ES6+, без сборки. Данные, вход и файлы — в [Supabase](https://supabase.com).
Никакой музыки, видео, игр, историй, лент по алгоритму и магазинов.

## Как это устроено

- Сайт статический — лежит на GitHub Pages.
- Supabase: Auth (почта и OAuth), PostgreSQL с Row Level Security, Storage (бакет `media`), Realtime.
- `js/data.js` держит данные в памяти и после каждого `F.save()` отправляет в базу только изменения.
- Права доступа обеспечивает база (`supabase/schema.sql`), а не браузер: ключ в `js/config.js` публичный по задумке.

## Настройка

1. **База.** Supabase → SQL Editor → вставить и выполнить `supabase/schema.sql`.
2. **Почта.** Authentication → Providers → Email → выключить *Confirm email* (иначе после регистрации придётся подтверждать письмо).
3. **Адреса.** Authentication → URL Configuration:
   - Site URL: `https://a23-aa.github.io/karakuli/`
   - Redirect URLs: `https://a23-aa.github.io/karakuli/**`
4. **Вход через соцсети** (по желанию). Authentication → Providers → включить Google / GitHub / Discord.
   Callback для настройки приложения у провайдера: `https://dwqaopsvburojrjxrdls.supabase.co/auth/v1/callback`.
   ВКонтакте и Яндекс Supabase не поддерживает из коробки.
5. **Публикация.** GitHub → Settings → Pages → Branch `main`, папка `/ (root)`.
6. Свой проект Supabase: поменять `supabaseUrl` и `supabaseKey` (publishable) в `js/config.js`.

## Админ-панель, юзернеймы, галочки

- У каждого свой уникальный `@юзернейм` (латиница, цифры, `_`, 5–32 символа). Занять его можно при регистрации; вошедшим через соцсети сайт предложит выбрать юзернейм сам. Служебные имена (admin, support и т. п.) заняты. По юзернейму ищут в поиске, а страница открывается по `profile.html?u=имя`.
- Три галочки: золотая с короной — владелец сайта (ставится только через SQL), синяя — подтверждённая личность, серая — блогер. Синюю и серую выдаёт админ в админ-панели.
- `admin.html` (виден только админам): статистика (онлайн сейчас, всего пользователей, записи, сообщения и т. д.), пользователи (галочки, блокировка, сброс юзернейма, удаление), редактирование и удаление записей, комментариев и сообществ. Личные сообщения админ не читает, только видит их количество.
- Заблокированный пользователь видит сайт, но не может публиковать записи, комментарии и сообщения.
- Права админа проверяет база (RLS и функции `admin_*`), а не браузер. Поля `badge`, `is_admin`, `banned` обычный пользователь изменить не может.

### Как стать владельцем

1. Зарегистрируйтесь на сайте.
2. Для уже работающей базы выполните `supabase/migration_002_admin.sql` в SQL Editor (в свежую базу он входит в `schema.sql`).
3. Выполните там же, подставив свою почту и юзернейм:

```sql
update public.profiles
   set is_admin = true, badge = 'owner', username = 'your_name'
 where id = (select id from auth.users where email = 'вашапочта@gmail.com');
```

## Подписчики, дни рождения, портал ивентов

- Подписаться можно на любого пользователя со страницы профиля. Записи тех, на кого вы подписаны, попадают в ленту «Главная», для них есть вкладка «Подписки» в «Новостях». Подписчики и подписки видны на профиле и во вкладках страницы «Друзья». Подписка не даёт доступа к закрытому профилю.
- В правой колонке показываются ближайшие дни рождения друзей и тех, на кого вы подписаны.
- Кнопка-портал (в шапке и в меню) ведёт на `events.html`: идёт ивент (с обратным отсчётом до конца), «Скоро» (таймер до начала) или «Ждите ивента». Время берётся с сервера, поэтому у всех оно одинаковое. Сами ивенты (игры) пока заглушка.
- Админ создаёт, запускает, завершает и удаляет ивенты во вкладке «Ивенты» админ-панели.
- Для этих функций нужен файл `supabase/migration_003_social.sql` (в чистую базу он входит в `schema.sql`). Пока он не выполнен, сайт работает, но подписки и ивенты не сохраняются.

## Безопасность и ограничения

- В `config.js` только публичный (publishable) ключ. Секретный `service_role` в репозиторий не кладут.
- Приватность профиля и сообщений, права на записи, комментарии и сообщения заданы политиками RLS.
- Профиль создаётся триггером при регистрации, удаление аккаунта — функцией `delete_my_account()`.
- Клиент при открытии каждой страницы загружает данные целиком, поэтому на бесплатном тарифе Supabase сайт рассчитан на небольшую сеть (порядка сотни пользователей, десятки одновременно). Главное ограничение бесплатного тарифа — трафик 5 ГБ в месяц и 200 одновременных realtime-соединений. Для роста нужна постраничная загрузка запросами и платный тариф.
- Дизайн: светлый плоский стиль, темы (светлая, тёмная, как в системе) и три акцентных цвета переключаются в настройках.
- Автотесты прогонялись на имитации supabase-js и на настоящем PostgreSQL для схемы. Живой проект проверьте вручную.
